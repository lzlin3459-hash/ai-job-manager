# 飞书多维表格「豆包求职管家」数据规范

技能读写用户飞书中的多维表格 Base（「豆包求职管家」），含两张表。运行前先通过飞书连接器确认表存在、字段名一致；字段名以实际表格为准（本文件为创建时的标准定义）。

## 表1：岗位库

| 字段 | 类型 | 说明 |
|---|---|---|
| 岗位名称 | 文本（主字段） | |
| 公司 | 文本 | |
| 行业板块 | 单选 | 食品企业 / 互联网企业 / 制造 / 零售 / 医疗健康 / 金融 / 教育 / 企业服务/SaaS / 其他 |
| 城市 | 文本 | 岗位所在城市（不限全国） |
| 薪资范围 | 文本 | 如"15-25k/月"、"面议" |
| 经验要求 | 文本 | 如"无经验（校招）"、"3-5年" |
| 学历要求 | 文本 | 如"本科"、"硕士" |
| 岗位链接 | 文本 | 企业官网/BOSS/猎聘的岗位详情链接 |
| 发布日期 | 日期 | 岗位发布时间（yyyy-MM-dd） |
| 截止日期 | 日期 | 岗位截止时间；长期开放可留空 |
| 关键词标签 | 多选 | 与求职意向/岗位方向匹配的标签（如：ToB销售、大客户销售、解决方案销售、商务BD、AI、云、KA、渠道、校招等） |
| 招聘类型 | 单选 | 校园招聘 / 社会招聘 / 均可（经验不限）；按简历教育状态校招社招分流（在校→校招优先） |
| 匹配度 | 数字 | 0-100，按求职意向+硬性条件+能力标签计算 |
| 状态 | 单选 | 待投 / 已投 / 面试中 / 已拒 / 已下架 |
| 抓取日期 | 日期 | 采集当天（yyyy-MM-dd） |
| 剩余天数 | 公式 | `DAYS([截止日期],TODAY())`——驱动"临期岗位"动态视图 |
| 备注 | 文本 | 优势/差距点评、来源说明等 |

**视图（持久化）**
- 表格视图：默认全量
- 高匹配岗位：筛选 匹配度 ≥ 80
- 临期岗位：筛选 剩余天数 介于 0 和 3（动态）

## 表2：投递追踪

| 字段 | 类型 | 说明 |
|---|---|---|
| 岗位名称 | 文本（主字段） | |
| 公司 | 文本 | |
| 行业板块 | 单选 | 同岗位库（食品企业 / 互联网企业 / 制造 / 零售 / 医疗健康 / 金融 / 教育 / 企业服务/SaaS / 其他） |
| 城市 | 文本 | |
| 岗位链接 | 文本 | |
| 投递日期 | 日期 | 实际投递当天 |
| 状态 | 单选 | 待投 / 已投 / 面试中 / 已拒 / Offer |
| 匹配度 | 数字 | 投递时岗位库的匹配度 |
| 面试时间 | 日期 | 进入面试后填写 |
| 反馈备注 | 文本 | 面试反馈、跟进记录 |

**视图（持久化）**
- 表格视图：默认全量
- 投递看板：看板（kanban）按「状态」分组——待投/已投/面试中/已拒/Offer 五列流转

## 回填规则

1. 新采集岗位入库：字段齐全（含招聘类型：校园招聘/社会招聘/均可（经验不限）），状态默认"待投"，抓取日期=当天；
2. 去重：按 岗位名称 + 公司 + 城市 判断，重复则不重复入库；
3. 超期处理：截止日期已过的记录，状态更新为"已下架"；
4. 匹配度回填：每次运行对"待投"岗位重算匹配度并覆盖，同时更新「备注」（优势/差距点评）；
5. 投递联动：用户投递后，将岗位从「岗位库」状态改为"已投"，并在「投递追踪」表新增一条记录登记流转。
